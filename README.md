# 打板模拟跟进（stock-board-paper）

用真实市场数据，**每天收盘后自动**推进两套打板策略的模拟账户，产出每日收益报告。
跑在 GitHub Actions 上，**你电脑关机也照常运行**。本目录就是云端仓库的根。

## 两件事，一套链路

| 需求 | 怎么满足 |
|---|---|
| **策略池的票持续增加** | `data/store.json` 是一份**只增不减**的累积数据集：交易日每天追加、新出现「曾连板 ≥2」的票自动纳入。**覆盖全量历史**（当前 221 个交易日，2025-11-13 起），云端可跑满 175 日窗口 |
| **模拟跟进交易** | 每天把新数据追进数据集后，对每套策略**从固定起点重放到今天**（直接调 `lib/strategy.js` 的 `runBacktest`，与网页回测**同一份引擎、零二次实现**），得到当日净值 / 持仓 / 明日候选 |
| **随时回测任意策略** | 线上 `backtest.html` 是本地回测控制台搬到云端：打开网页改参数就能回测，数据集来自仓库 `data/store.json`（每日自动追加）⇒ **本机文件全删也不影响** |

重放法的好处：**不需要维护易损的状态文件**——账户状态永远可以从「起点 + 数据集」完整重算出来，任何时候重跑结果都一致，数据坏了可以整体重建。

## 两个线上页面

| 地址 | 用途 |
|---|---|
| `https://zyh19870426.github.io/stock-board-paper/` | **每日收益看板**：两套策略的收益曲线（7/30/60/90/全部）、指标卡、买卖记录、持仓与次日待买 |
| `https://zyh19870426.github.io/stock-board-paper/backtest.html` | **策略回测（云端）**：与本地「打板策略模拟器」同一份源码生成，可改任意参数，数据集自动更新 |

⚠️ 云端回测页由 `node build-cloud.js` 从上层 `index.html` 生成（只做 4 处替换：标题/导航、去掉 `output/dataset.js`、注入 `__DS_URL__='data/store.json'`、seal 路径改 `data/`）。
**改了上层 `index.html` 之后必须重跑 `node build-cloud.js`**，否则线上页会停在旧版本 —— `node build-cloud.js --check` 可校验是否漂移（也是 `check-consistency.js` 的一节）。

## 文件说明

| 文件 | 作用 |
|---|---|
| `daily.js` | ★每日入口：抓数 → 追加数据集 → 重放两套策略 → 日报 → 推送 |
| `lib/strategy.js` | 策略引擎（与上层项目 `stock-board-sim/lib/strategy.js` **同一份**，用 `node sync-engine.js` 同步） |
| `lib/store.js` | 累积数据集的播种 / 每日增量 / 读写 |
| `lib/fetch.js` | 股票池（东财 clist 分页，失败回退快照）+ 全市场日线（腾讯 ifzq，新浪兜底） |
| `config.json` | ★策略清单（可任意多套，每套独立 10 万本金、独立账户）：参数、起点、本金。**改这里就行**，下次运行生效 |
| `build-cloud.js` | ★从上层 `index.html` 生成云端回测页 `backtest.html`；`--check` 校验是否漂移 |
| `reset-store.js` | 一次性修复脚本：把累积数据集升级为「全量历史」（`--dry` 可预演） |
| `data/store.json` | 累积数据集（日期只增、票池只增，**全量历史**） |
| `data/seal-map.json` | 封板强度映射（云端回测页「封板强度优先」排序用） |
| `data/dashboard.json` | 看板数据（每日全量重写：净值曲线 + 全部成交） |
| `data/universe.json` | 股票池快照（云端优先在线拉，拉不到就用它兜底） |
| `reports/YYYY-MM-DD.md` | 每日日报 |
| `reports/summary.json` | 两套策略的最新摘要（给页面/程序读） |
| `.github/workflows/daily.yml` | 每个交易日 15:40（北京时间）自动跑 |

## 每日日报里有什么

每个策略一块：

- **当日盈亏（元）/ 当日收益率 / 累计收益率 / 总资产**
- 今日买入（开盘价成交）、今日卖出（含原因）、今日弃买
- 当前持仓（代码 / 股数 / 买入价 / 成本）
- **次日待买清单**（今日收盘选出，下一交易日开盘执行）

## 滚动验证（每 20 交易日复检）

**为什么不是「显著性检验」**：日波动 5.29%、日均超额 0.199% ⇒ 同效应需要
n≈2831 交易日（11.3 年）才可能显著。打板策略上这个检验**不可能达成**。
所以系统改用「**监控何时失效**」替代「**一次性证明有效**」——2~3 个月就能有答案。

看板顶部常驻一条状态条（`lib/rolling.js` 计算，随每日收盘跑更新，盘中快照带最新价重算）：

| 状态 | 触发条件 | 含义 |
|---|---|---|
| 🟢 方向成立 | 近 20 日跑赢静态最强，且 60 日内 ≥2/3 窗口为正 | 照常跟随 |
| 🟡 观察中 | 近 20 日跑输静态，或仅 ≤1/3 窗口为正 | 降低仓位 / 留意 |
| 🔴 建议降级 | 连续 ≥20 个 20 日窗口跑输且累计 ≤−5%，或 0/3 窗口为正 | 方向可能已失效，停下来复盘 |
| ⚪ 样本不足 | 不足 22 个交易日 | 继续等 |

三项指标（全部只用 ≤ 当日数据，无未来函数）：
1. **近 20 交易日**：M2 是否跑赢「静态最强」（按期输赢，不看累计）
2. **连续跑输**：连续多少个 20 日窗口跑输 + 累计跑输幅度
3. **多窗口方向**：近 60 日内 5/10/20 日三个窗口各自是否为正

结果落三处：看板顶部状态条 · `data/dashboard.json` 的 `rolling` 字段 ·
`data/rolling.json`（保留最近 120 次快照，可追历史轨迹）。

## 滑点实测记录表（半自动模式必备）

回测最大的不确定是**滑点**。审计显示：单边 0.5% 滑点 ⇒ 总收益从 +307% 衰减到 +133%；
单边 1% ⇒ 只剩 +11.8%；单边 2% ⇒ −80.6%。**你自己的滑点是多少，只有实测才知道。**

```bash
# 1) 每次真实下单后，追加一行到 data/slippage-log.csv
#    （表内有填写说明；planPrice 抄系统给的「开盘价 / 收盘价」计划价）
# 2) 攒够 20 笔以上，跑汇总
node slippage.js
```

输出：单边滑点均值 / 中位 / P90 / 最差 + 不利成交占比 + 对照审计区间（落在哪个档），
并写 `data/slippage-summary.json`。`n<20` 时噪声大，仅供参考。

## 当日分时增量采集（长期追踪 09:30 买入偏离）

分钟级数据源都只回溯约 1 个月（新浪 scale=5 → 22 交易日 / 腾讯 m5 → 7.5 天），
所以「09:30–9:35 买入 vs 竞价开盘价」实测只能拿到 12 笔。

**解法**：每天收盘任务顺手把「当日候选 + 持仓」的关键 bar 存进
`data/minute-history.json`（只增不减、按 code+date 去重、留最近 400 交易日）。
几个月后自然累积到 n=200+，那时这个偏离分布就可信了。

```bash
node analyze-minute-log.js   # 读累积数据，输出偏离分布（含样本量提示）
```

采集失败（限流/停牌）**绝不影响主流程** —— 有 90s 时间预算 + try/catch 兜底。

## 部署（一次性）

```bash
# 1) 本地先跑通一遍（会用上层项目的 output/dataset.json 播种）
node daily.js --dry          # 只看不写
node daily.js --reseed       # 真跑：播种 + 抓取 + 出第一份日报

# 2) 同步引擎后，把这个目录推成 GitHub 仓库 stock-board-paper
node sync-engine.js

# 3) 在仓库 Settings → Secrets 加推送密钥（可选，不加则只看仓库报告）
#    PUSHPLUS_TOKEN / SENDKEY / WECOM_WEBHOOK 三选一即可

# 4) Actions 页面手动触发一次 workflow_dispatch 验证，之后每个交易日自动跑
```

## 手动命令

```bash
node daily.js                # 正常跑（写文件 + 推送）
node daily.js --dry          # 只打印，不写不推
node daily.js --no-fetch     # 跳过抓取，用现有数据集重算（验证/修复用）
node daily.js --reseed       # 从上层 output/dataset.json 重新播种（全量历史；会丢掉已累积的增量，慎用）
node sync-engine.js          # 同步引擎（改了 lib/strategy.js 之后必须跑）
node build-cloud.js          # 重新生成云端回测页（改了上层 index.html 之后必须跑）
node build-cloud.js --check  # 只校验云端页是否与 index.html 同步
node reset-store.js --dry    # 预演「数据集升级为全量历史」的合并结果
node slippage.js             # 汇总真实成交滑点（读 data/slippage-log.csv）
node slippage.js <csv路径>   # 指定其它记录表
```

> 买入挂单时点：推送里已提示「09:30–09:33」，越早越接近竞价开盘价。
> 实测（n=12）09:30–9:35 买入相对开盘价平均仅 **+0.35%**、双向对称，
> 但越晚单笔波动越大（±5~10%）⇒ 尽早挂、别追价。

## 加 / 删策略后，看板什么时候变

- 在回测页点「加入模拟」/「移出模拟」会写云端 `config.json` 并**立即触发一次 workflow**。
- 手动触发这一次**通常没有新交易日**（当天已经跑过，或数据源还没更新）。
  此时脚本**不再提前退出**，仍会按当前 `config.json` 重放并重写 `data/dashboard.json`
  ⇒ 2~5 分钟后看板就出现新策略。
  > 早期版本在「没有新交易日」时直接 `return`（连看板数据都不写），结果是
  > **手动加的策略永远不显示，必须等到下一个真·新交易日才连带生效**。
- 反过来，没有新交易日时**不会写日报、不会推送**，账户与数据集也不动（幂等重放）。
- 看板支持**任意数量**策略（8 色循环）：曲线按**日期**对齐，后加入的策略从自己的起点开始画，
  不会把短序列拉伸到整幅或整条消失。
- `startDate` 决定「每日收益曲线」从哪天开始。若设成数据集的最后一天，曲线起初就只有 1 个点，
  每天往前推 1 天；想看历史表现请用 `backtest.html` 或回测页的「方案对比表」（多窗口历史回测）。

## 口径与边界（与回测页一致）

- T 日收盘选股 → **T+1 开盘价**买入；一字涨停开盘 → 弃买（名额空过，不补位可配）
- ★**A 股 T+1：买入当日不可卖出** → 卖出判定**从买入次日起**。所以「断板即出」实际是 **T+2 起**每个交易日 14:57 看是否封住涨停、没封才卖。回测严格遵守（0 笔当日买卖）
- **断板即出**：**14:57 前看是否封住涨停，未封则在收盘集合竞价挂单卖出**（14:57–15:00 集合竞价期间不可撤单，成交的统一价＝当日收盘价 → 与回测价格假设一致，也是唯一可实际执行的时点）/ 亏损止损 / 最高价回撤止损 / 最长持有上限
- 跌停锁死卖不出 → 顺延下一交易日（引擎已处理，含开盘一字跌停）；**跌停后不要改成次日开盘卖**——跌停次日普遍大幅低开（实测均值 −3.99%），且次日一字跌停开盘时开盘卖同样卖不掉，两方案等价（见 `../T+1与跌停处置核验.md`）
- **模拟盘按开盘价 / 触发价理想成交，未计滑点与冲击成本**；不构成投资建议
- 数据源：腾讯 ifzq 不复权日线（220 根）→ 新浪兜底；股票池东财 clist → 本地快照兜底
- 非交易日自动跳过（没有新交易日数据就不动账户、不出日报）
