1 · 当前线上配置（S3 全参数）

{
  "slots": 2,                              // 资金分 2 份，最多同时持 2 只
  "minLbc": 0, "maxLbc": 2,                // 只买首板（1 板）：0 < 板数 < 2
  "stopLossPct": 20,                       // 亏损止损 −20%
  "trailPct": 25,                          // 移动回撤线 25%（自买入后最高价，日内实时上移）
  "exitMode": "break",                     // 离场固定：断板即出（14:57 未封 → 收盘集合竞价卖，成交价＝收盘价）
  "maxHoldDays": 10,                       // 最长持有 10 个交易日
  "sortBy": "amtRatio",                    // 排序：量能比降序（T日成交额 ÷ 前5日均额）
  "minAmtRatio": 1.5,                      // 量能比下限 1.5
  "allocMode": "dynamic",                  // 每份 = 当前总资产 ÷ 份数
  "refillOnSkip": false,                   // 弃买不补位
  "skipLimitOpen": true,                   // 一字涨停开盘弃买（真实约束）
  "trailIntraday": true,                   // 回撤线按日内最高价移动
  "boardFilter": "main",                   // 主板 + 创业板，排除科创/北交所
  "maxGem": 1,                             // ★本版新增：创业板当日最多持 1 只
  "delistExit": true,                      // 退市/摘牌按最后可得价强制清仓
  "gateYz": { "q": 0.80, "win": 250 },     // 情绪闸门：再封率 > 近250日 80% 分位 ⇒ 次日不开新仓
  "ddStop": { "ddPct": 0.35, "pauseDays": 60 }  // 回撤熔断：自高点回撤 ≥35% ⇒ 停手 60 个交易日
}

人话版规则（可直接照着做）

  • 每天收盘后选股：全市场挑首板、量能比 ≥ 1.5 的票，按量能比从高到低排；创业板最多 1 只，其余名额给主板；次日一字涨停开盘就跳过、不补位。
  • 第二天开盘买入，每份金额 = 当时总资产 ÷ 2。
  • 持仓盯两条线：亏 20% 砍；或从买入后最高价回撤 25% 砍。
  • 断板即出：买入当日不能卖（T+1），从买入次日起每个交易日 14:57 看是否封板 —— 没封住就在收盘集合竞价挂单卖，成交价＝收盘价。
  • 最多拿 10 个交易日，到点无条件走人。
  • 两个停手开关（只拦开新仓，持仓照常卖）：闸门 —— 昨日涨停股今日再封率高于近 250 日 80% 分位 ⇒ 明日不开新仓；熔断 —— 净值自高点回撤 ≥35% ⇒ 停手 60 个交易日，期满重新起算。

四道防伪检验（后续任何新改动都照此做）

  • 对称性：限制主板最多 1 只 → 收益小升但 t↓（3.15→3.04）、回撤↑（→51.5%）；只有限创业板做到三项全优。
  • 安慰剂：按代码奇偶随机切一半股票、限其最多 1 只 → 3484%（−20%）、t↓、回撤↑，方向完全相反 ⇒ 效果来自创业板本身，不是集中度也不是巧合。
  • 邻域：固定 q=0.80 扫 trail 21~29 → 9/9 全胜且 t 每一格都提升。
  • 压力测试：创业板单笔被打到 −2% 时本档仍 +178%（现状仅 +17%）；盈亏平衡点 −1.57% → −2.31%。
红线：q ≥ 0.82 时 maxGem=1 出现断崖（−1651 ~ −3624pp）。以后调 q 必须重跑本节检验。

3.4 为什么不做「跨年自动换档」（M2）

  • M2 在 1488 个交易日里切换 266 次，平均每段只持有 5.6 个交易日；全区间 −99.1%，跑输所有固定档位。
  • 每年「最强档位」确实不同（2021 五板 +107%、2022/2024/2025 三板最好、2026 首板最好），但跟随逻辑抓不住 —— 它用「近 10 日净值涨幅」做判据，本质是追已经涨完的那一段。
  • S3 的利润结构：86% 的笔只有 1 板（单笔 −0.84%），14% 走出连板的笔单笔 +11.92%，连板溢价 12.76pp/笔。频繁切换会恰好切掉这 14%。
  • 结论：M2 保留展示，不作操作依据。

4 · 已否决的改动（存档 · 别再试第二次）

改动实测否决原因
① 连续仓位 sizeYz（仓位随再封率连续收缩，替代闸门硬开关）4383% → 787%原始假设「越冷越满仓」与实测相反：温度与收益是倒 U —— 最冷 +0.26%、中性 +1.61% 最好、最热 +0.27%。倒 U 修正版 +3337%（t=2.97）仍不如现网
② 只做主板 excludeGem4383% → 1783%收益腰斩、t 降到 2.54、回撤反而升到 54.9%。正确做法是限 1 只而非剔除
③ 封板率 seal 因子无法测历史数据里封板率全为 null；改用 closePos 代理后改善在邻域内乱跳、无单调性、方向自相矛盾 → 噪声
④ 份数甜点（3 份 / 5 份）3 份 2462%（后半仅 83%）；5 份 1592%（t 3.53、回撤 43.1%）裁决：都不动，只跑 S3
⑤ 跨年自动换档（M2 类）−99.1%、切换 266 次见 3.4
⑥ S1/S2/S4 上补量能比 / 闸门等因子—裁决：不动，只跑 S3，其余仅作对照

6 · 后续更新 SOP

  • 1 本地改：只改 paper/config.json。
  • 2 扫网格：node hist-gate-grid.js —— 看是否单调、是否有邻域支撑。
  • 3 样本外：node hist-oos-check.js —— 前后半段双胜 + 后半 t 不降。
  • 4 防伪三件套：对称性对照 / 安慰剂 / 邻域扫（trail × q 25 格）。模板见 hist-gem-cap.js。
  • 5 备份：paper/_rollback/<名字>-<时间戳>/。
  • 6 同步引擎（若改了 lib）：cd paper && node sync-engine.js。
  • 7 重生成页面：node build-cloud.js（云端回测页）、node build-standalone.js（单文件版）。
  • 8 推送：GH_TOKEN=xxx node paper/push-github.js，等 daily.yml 跑完核对。
  • 9 看板核对：主策略徽章、风控状态、成交明细列数。
红线：
· 改 gateYz.q 到 ≥0.82 必须重跑 maxGem 检验（断崖）。
· 只看「全区间收益」就上线 = 赌博，必须过样本外双胜。
· 短窗口（滚动 2 年 / 逐年）对复利策略判别力天然不足 —— 实测安慰剂 3/8、全区间最差的变体反而 5/8。以「全区间复利路径 + t 值 + 压力测试」为准。
· 引擎默认值只加默认关闭的开关，保证老配置行为不变。
